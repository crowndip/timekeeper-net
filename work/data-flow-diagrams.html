🔒 Parental Control System - Data Flow Diagrams

1. Client Startup & Registration

When: Client service starts (system boot or service restart)
Purpose: Register computer with server and sync local users
sequenceDiagram participant Client as Client Service participant Server as Web Server participant DB as PostgreSQL Client->>Server: POST /api/client/register
{ComputerName, OS} Server->>DB: INSERT/UPDATE Computer DB-->>Server: Computer ID Server-->>Client: {ComputerId, ApiKey} Client->>Client: Save ComputerId to
/etc/parental-control/computer-id Client->>Client: Get local users
(loginctl/WMI) Client->>Server: POST /api/client/sync-users
{ComputerId, Usernames[]} Server->>DB: INSERT Users (if not exist) DB-->>Server: User records Server-->>Client: {Success}

2. Time Tracking (Every 60 seconds)

When: Every tick interval (default 60 seconds)
Purpose: Track active sessions and record time usage
sequenceDiagram participant Client as Client Service participant Session as Session Monitor participant Cache as Local Cache (SQLite) participant Server as Web Server participant DB as PostgreSQL Client->>Session: GetActiveSessions() Session->>Session: loginctl list-sessions
(Linux) Session-->>Client: [UserSession] loop For each session Client->>Session: IsSessionIdleAsync(sessionId) Session->>Session: loginctl show-session
-p LockedHint Session-->>Client: isLocked (true/false) alt Screen Unlocked Client->>Cache: IncrementUsage(user, 1 active, 0 idle) else Screen Locked Client->>Cache: IncrementUsage(user, 0 active, 1 idle) end end Client->>Cache: GetPendingRecords() Cache-->>Client: [UsageRecords] Client->>Server: POST /api/client/usage
{ComputerId, Username, Minutes} Server->>DB: SELECT TimeProfile (active) Server->>DB: SELECT TimeUsage (today) Server->>DB: SELECT TimeAdjustments (today) Server->>DB: INSERT/UPDATE TimeUsage Server->>DB: UPDATE Computer.LastSeenAt DB-->>Server: TimeRemaining, ShouldEnforce Server-->>Client: {TimeRemainingMinutes, ShouldEnforce} Client->>Cache: MarkAsSynced(recordIds)

3. Time Calculation (Server-Side)

When: On every usage report from client
Purpose: Calculate remaining time based on limits and usage
sequenceDiagram participant Server as Web Server participant TimeCalc as TimeCalculationService participant DB as PostgreSQL Server->>TimeCalc: CalculateTimeRemainingAsync(userId, date) TimeCalc->>DB: SELECT TimeProfile
WHERE UserId AND IsActive DB-->>TimeCalc: Profile (daily limits, weekly limit) TimeCalc->>DB: SELECT SUM(MinutesUsed)
FROM TimeUsage
WHERE UsageDate = today DB-->>TimeCalc: usedToday TimeCalc->>DB: SELECT SUM(MinutesAdjustment)
FROM TimeAdjustments
WHERE AdjustmentDate = today DB-->>TimeCalc: adjustments TimeCalc->>TimeCalc: dailyRemaining =
dailyLimit - usedToday + adjustments alt Has Weekly Limit TimeCalc->>DB: SELECT SUM(MinutesUsed)
FROM TimeUsage
WHERE UsageDate >= weekStart DB-->>TimeCalc: usedThisWeek TimeCalc->>TimeCalc: weeklyRemaining =
weeklyLimit - usedThisWeek TimeCalc->>TimeCalc: return MIN(dailyRemaining, weeklyRemaining) else No Weekly Limit TimeCalc->>TimeCalc: return dailyRemaining end TimeCalc-->>Server: timeRemaining (minutes)

4. Enforcement (When Time Runs Out)

When: Time remaining ≤ 0 or outside allowed hours
Purpose: Terminate user session to enforce time limits
sequenceDiagram participant Client as Client Service participant Enforcement as EnforcementEngine participant TimeCalc as TimeCalculationService participant Session as Session Monitor participant OS as Operating System Client->>Enforcement: CheckAndEnforceAsync(response) Enforcement->>Enforcement: Check timeRemaining <= 0 alt Time Expired Enforcement->>TimeCalc: IsWithinAllowedHoursAsync(userId, now) TimeCalc-->>Enforcement: isAllowed (true/false) alt Outside Allowed Hours OR No Time Enforcement->>Session: GetActiveSessions() Session-->>Enforcement: [UserSession] loop For each session Enforcement->>OS: loginctl terminate-session
(Linux) Note over OS: User is logged out end Enforcement->>Enforcement: Show notification
"Time limit reached" end end

5. Admin Authentication & Edit Operations

When: Admin wants to edit users, profiles, or time limits
Purpose: Secure server-side authentication for mutations
sequenceDiagram participant Browser as Web Browser participant UI as Blazor UI participant AuthAPI as Auth Controller participant AuthSvc as AuthService participant Session as Server Session participant API as Protected API participant DB as PostgreSQL Browser->>UI: Click "Unlock Editing" UI->>Browser: Navigate to /admin-auth Browser->>UI: Enter password UI->>AuthAPI: POST /api/auth/login
{Password} AuthAPI->>AuthSvc: ValidatePassword(password) AuthSvc->>AuthSvc: Compare with
LimitAdministratorPassword alt Valid Password AuthSvc->>Session: SetString("IsAuthenticated", "true") Session-->>AuthSvc: Session cookie created AuthAPI-->>UI: 200 OK {success: true} UI->>Browser: Navigate back to page Browser->>UI: Page shows edit controls UI->>API: POST /api/users
{UserData} API->>AuthSvc: IsAuthenticated() AuthSvc->>Session: GetString("IsAuthenticated") Session-->>AuthSvc: "true" alt Authenticated API->>DB: INSERT User DB-->>API: User created API-->>UI: 200 OK {success: true} else Not Authenticated API-->>UI: 401 Unauthorized end else Invalid Password AuthAPI-->>UI: 401 Unauthorized UI->>Browser: Show error message end

6. Time Adjustment (Emergency Time Grant)

When: Admin grants extra time to a user
Purpose: Allow temporary time extension for special circumstances
sequenceDiagram participant Browser as Web Browser participant UI as Users Page participant API as Users Controller participant Auth as AuthService participant DB as PostgreSQL participant Client as Client Service Browser->>UI: Click "Adjust Time" for user UI->>Browser: Show dialog (enter minutes) Browser->>UI: Enter +30 minutes UI->>API: POST /api/users/{id}/adjust-time
{MinutesAdjustment: 30} API->>Auth: Check [RequireAuth] Auth-->>API: Authenticated ✓ API->>DB: INSERT TimeAdjustment
{UserId, Date: today, Minutes: 30} DB-->>API: Adjustment saved API-->>UI: 200 OK {success: true} UI->>Browser: Show success message Note over Client: On next tick (within 60s) Client->>API: POST /api/client/usage API->>DB: SELECT TimeAdjustments
WHERE UserId AND Date = today DB-->>API: adjustments = +30 API->>API: timeRemaining =
limit - used + 30 API-->>Client: {TimeRemainingMinutes: increased}

7. Tray Icon Status Updates

When: Every 30 seconds (tray app timer)
Purpose: Show remaining time in system tray
sequenceDiagram participant Tray as Tray Icon App participant Server as Web Server participant DB as PostgreSQL participant UI as System Tray loop Every 30 seconds Tray->>Server: POST /api/client/usage
{ComputerId, Username, IsQuery: true} Note over Tray: IsQuery=true means
no usage to report Server->>DB: SELECT User WHERE Username Server->>DB: SELECT TimeProfile (active) Server->>DB: SELECT TimeUsage (today) Server->>DB: SELECT TimeAdjustments (today) DB-->>Server: Calculate time remaining alt Parent Account Server-->>Tray: {TimeRemainingMinutes: 2147483647} Tray->>UI: Update tooltip:
"Parent - No time limit" else Child Account Server-->>Tray: {TimeRemainingMinutes: 45} Tray->>UI: Update tooltip:
"45m remaining" end end

8. Offline Mode (Server Unavailable)

When: Server is unreachable (network down, server offline)
Purpose: Continue enforcement using cached data
sequenceDiagram participant Client as Client Service participant Cache as Local Cache (SQLite) participant Server as Web Server participant Enforcement as EnforcementEngine Client->>Cache: GetPendingRecords() Cache-->>Client: [UsageRecords] Client->>Server: POST /api/client/usage Note over Server: Server unreachable Server--xClient: Connection timeout Client->>Client: Log warning:
"Server unavailable, using offline mode" Client->>Enforcement: CheckAndEnforceOfflineAsync(usageData) Enforcement->>Cache: Get last known time limit Enforcement->>Enforcement: Calculate local time remaining
(estimate based on cache) alt Time likely expired Enforcement->>Enforcement: Enforce logout
(conservative approach) else Time likely remaining Enforcement->>Enforcement: Allow continued use end Note over Client: Usage records stay in cache
Will sync when server returns

9. Profile & Allowed Hours Management

When: Admin creates/edits time profiles or allowed hours
Purpose: Configure time limits and usage windows
sequenceDiagram participant Browser as Web Browser participant UI as Profiles Page participant API as Profiles Controller participant Auth as AuthService participant DB as PostgreSQL Browser->>UI: Create new profile UI->>Browser: Show form (daily limits, weekly limit) Browser->>UI: Enter limits:
Mon-Fri: 120min, Sat-Sun: 180min UI->>API: POST /api/profiles
{UserId, Name, MondayLimit: 120, ...} API->>Auth: Check [RequireAuth] Auth-->>API: Authenticated ✓ API->>DB: BEGIN TRANSACTION alt IsActive = true API->>DB: UPDATE TimeProfiles
SET IsActive = false
WHERE UserId (deactivate others) end API->>DB: INSERT TimeProfile
{UserId, Name, Limits, IsActive} DB-->>API: Profile created API->>DB: COMMIT API-->>UI: 200 OK {success: true, data: profile} Note over UI: Profile immediately active
Client will use on next tick opt Add Allowed Hours Browser->>UI: Add time window:
Mon-Fri 15:00-20:00 UI->>API: POST /api/profiles/{id}/allowed-hours API->>DB: INSERT AllowedHours
{ProfileId, DayOfWeek, StartTime, EndTime} DB-->>API: Hours saved API-->>UI: 200 OK end
